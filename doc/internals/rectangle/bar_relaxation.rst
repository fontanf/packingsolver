Bar relaxation
==============

Objectives
----------

This algorithm computes a bound for the :code:`knapsack`, :code:`feasibility`, :code:`bin-packing` (with a single bin type) and :code:`variable-sized-bin-packing` objectives. It doesn't produce solutions.

It is also used by the :ref:`Benders decomposition <internals_rectangle_benders_decomposition>` to lift its no-good cuts.

Principle
---------

It is the *bar relaxation* of Scheithauer (1999), in two dimensions, generalized to several bins of possibly different bin types. Instead of requiring a 2D placement of the items, each bin is sliced into unit-height horizontal *row-bars*, one-dimensional bins of capacity the width of the bin, and into unit-width vertical *column-bars*, one-dimensional bins of capacity the height of the bin. An item of width :math:`w` and height :math:`h` placed in the bin crosses :math:`h` row-bars, taking a length :math:`w` in each, and :math:`w` column-bars, taking a length :math:`h` in each. The relaxation only requires that the items packed can be distributed among the bars this way, which is a necessary condition for a packing.

Model
-----

**Input**:

* bin types :math:`t = 1, \ldots, m`; for each bin type :math:`t`: a width :math:`W_t`, a height :math:`H_t`, a cost :math:`c_t`, and a minimum and a maximum number of copies :math:`m_t` and :math:`M_t`
* item types :math:`j = 1, \ldots, n`; for each item type :math:`j`: a profit :math:`p_j` and a number of copies :math:`q_j`; an item type which can be rotated is split into two *oriented variants*; for each oriented variant :math:`i`: its width :math:`w_i` and its height :math:`h_i`, and :math:`j(i)` its item type
* for each bin type :math:`t`, the *row patterns* :math:`q`, sets of oriented variants whose widths sum to at most :math:`W_t`, and the *column patterns* :math:`p`, sets of oriented variants whose heights sum to at most :math:`H_t`; :math:`a_{iq}` (resp. :math:`b_{ip}`) is the number of copies of variant :math:`i` in pattern :math:`q` (resp. :math:`p`)

**Variables**:

* :math:`k_t \ge 0`: number of bins of type :math:`t` used
* :math:`n_{i,t} \ge 0`: number of copies of oriented variant :math:`i` packed in bins of type :math:`t`
* :math:`y_q^t \ge 0`: number of row-bars of bin type :math:`t` filled with row pattern :math:`q`
* :math:`x_p^t \ge 0`: number of column-bars of bin type :math:`t` filled with column pattern :math:`p`

**Objective**: depending on the objective

.. math::

   \max \sum_{i,t} p_{j(i)} \, n_{i,t}
   \qquad \text{(knapsack)}

.. math::

   \min \sum_t c_t \, k_t
   \qquad \text{(bin packing, variable-sized bin packing)}

For the :code:`feasibility` objective, there is no objective: only the constraints.

**Constraints**:

* Row-bars: an item of height :math:`h_i` crosses :math:`h_i` row-bars

.. math::

   \forall i, t \qquad \sum_q a_{iq} \, y_q^t = h_i \, n_{i,t}

* Column-bars: an item of width :math:`w_i` crosses :math:`w_i` column-bars

.. math::

   \forall i, t \qquad \sum_p b_{ip} \, x_p^t = w_i \, n_{i,t}

* Number of row-bars: a bin of height :math:`H_t` has :math:`H_t` row-bars

.. math::

   \forall t \qquad \sum_q y_q^t \le H_t \, k_t

* Number of column-bars: a bin of width :math:`W_t` has :math:`W_t` column-bars

.. math::

   \forall t \qquad \sum_p x_p^t \le W_t \, k_t

* Number of bins

.. math::

   \forall t \qquad m_t \le k_t \le M_t

* Item copies: each item type is packed at most (:code:`knapsack`) or exactly (other objectives) its number of copies

.. math::

   \forall j \qquad \sum_{i : j(i) = j} \; \sum_t n_{i,t} \le q_j

Solution method
---------------

The patterns are generated by column generation. The pricing problem of the row patterns (resp. column patterns) of a bin type is a bounded 0-1 knapsack problem over the oriented variants fitting in the bin type, of capacity :math:`W_t` (resp. :math:`H_t`), maximizing the sum of the dual values of the linking constraints. It is solved with the :ref:`onedimensional <internals_onedimensional>` algorithms.

The optimal value of the linear program is a bound: a profit bound for the :code:`knapsack` objective, a cost bound for the :code:`variable-sized-bin-packing` objective, converted into a number of bins for the :code:`bin-packing` objective. For the :code:`feasibility` objective, an infeasible linear program proves that the instance is infeasible.

The defects and the fixed items are not modeled. Dropping them only relaxes the problem, so the bounds stay valid, but they may be weaker on the instances where they matter.

Automatic selection
-------------------

It is computed automatically with a single bin, a single bin type of width and height at most 100, and the :code:`knapsack` or :code:`feasibility` objective (the size of the model grows with the dimensions of the bins). It can be forced with :code:`--use-bar-relaxation 1` (CLI) or :code:`use_bar_relaxation` (Python).
